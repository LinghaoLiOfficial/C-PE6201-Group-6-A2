# 第 3 节 评估证据说明了什么

我们评估了 45 个保险理赔案例，其中 30 个由团队原创，15 个来自教师参考资料。30 个普通案例各运行一次，15 个负例各运行三次，每种配置共 75 次试验。代码检查评估决定、明确的触发条件、缺失项、金额、工具证据及受控写入；独立的 GPT-4.1-mini 评估解释质量。综合通过要求两种检查同时通过。D5(a) 在无网络环境下复现了 75/75 的 scripted 代码检查通过结果，执行错误为零；这验证了系统整合，而不是 live 模型准确率。

五个模型家族使用相同的冻结 v2 配置；DeepSeek v1 另用于提示词对照。表 3 列明所有分母。DeepSeek v2 综合通过 71/75（94.7%），v1 为 64/75（85.3%），观察到 9.3 个百分点的提升。其整套运行成本为 0.2829 美元；最昂贵的 Claude Haiku 配置花费 1.3562 美元，却仅通过 28/75（37.3%）。成本按实测 API token 和冻结单价计算，不包含 judge 与人工兜底。运行支出更低的模型未达到 DeepSeek 的可靠性。

协议遵从性解释了大量模型差异。Qwen 在 51/75 次试验中生成了协议禁止的 Observation 内容；Gemini 出现 70/75 次执行失败，包括四次触发步数上限。这些失败全部保留在分母内。六种配置合计代码通过 203/450、综合通过 200/450，保留了 237 次执行失败。统一 judge 审查了全部 213 次已完成试验。这些结果衡量的是模型与严格 ReAct 协议及证据要求的适配程度，而非通用智能。

负例揭示了看似正确的决定背后的缺陷。年度限额案例 CLM-8925 中，Mistral 在两次完成的重复试验中正确升级人工处理，却把总额写成 13,200，而非 11,400；尽管代码检查通过，judge 仍判定二者不通过。在团队原创的 CLM-16105 中，Claude 正确要求提供服务日期有效的授权，却在三次重复试验中都缺少规定的文件检查证据。DeepSeek 的负例综合通过数为 43/45，Mistral 为 6/45。DeepSeek 有一次重复理赔案例的判断仍不确定，未计为通过。

重复负例还揭示了不稳定性：DeepSeek 在 15 个负例中的 13 个上三次均通过，Qwen 和 Mistral 则一个也没有。样本规模较小、案例为人工构造，加上判断不确定性，结论仅支持继续验证，不能构成部署认证。评分提示词和逐次记录均已保留供核查。部署决定需要预先确定阈值并补充证据。
